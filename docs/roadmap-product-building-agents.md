## 1. Product definition (founder language)

**DeliverX is a supervised workforce of agents that build products with you — in sequence, on a stage you can watch and stop.**

You bring a product question. An initiating PM takes the brief. Specialists then **produce the next real artefact in the build chain** (frame → research → options → your decision → pack →, over time, design / prototype / verify) — not another dashboard panel, not a status chip saying “busy.”

Humans own every gate. Agents draft and hand off. Nothing external or billable runs without an explicit yes. Every artefact says how it was made (model or simulated). Gaps stay labelled. Outcomes are only claimed when observed.

That is the product: **future product-building agents**, supervised — not a Command ops console, and not “AI chat that talks about building.”

---

## 2. What that implies (non-negotiables)

1. **Sequence over dashboard.** The primary story is the next build beat and its artefact — not KPIs, catalogues, or stacked admin panels.
2. **Agents produce; humans approve.** Plan, design, release, and any Act externally stay human-only. Agents and schedulers may block on a gate; they never pass one.
3. **Handoffs are contracts.** Downstream work does not consume a failed, blocked, or unapproved upstream. Failures are persisted and named — never dropped.
4. **Honesty is secondary narrative.** Simulated drafts, missing providers, and research gaps are badges and footnotes — never the opening plot.
5. **No fabricated customers, interviews, or observed outcomes.** Rehearsal content is labelled; only founder-supplied notes count as evidence.
6. **Usage ceilings hard-stop** further billable steps. Stub / deterministic drafts when model keys are absent; disclose generation mode on every artefact.
7. **Additive persistence & workspace isolation.** Prefer restyling existing supervised / `wf_*` spine before new product forks. No Lovable history rewrite.
8. **One theatre.** Overview foyer → supervised Acts → living work. Specialists = cast for the case. Project = product memory shelf. Programme stays Lab until it speaks the same language.
9. **Students learn by building alongside agents in the same environment** — career/coaching surfaces stay retired.
10. **Out of scope remains out:** books/publishing, regulated healthcare, always-on 150-role tourism, agents office as primary, voice until typed path is solid.

## 3. Gap vs today (honest)

### What exists (spine is real)

| Layer | Today |
| --- | --- |
| **Supervised decision loop** | One-liner → PM brief → plan gate → research/work pass → options → owner decision → pack → owner-supplied outcome / follow-up |
| **Phases B–E (`2040eaa`)** | Living research scene from persisted events; banded Wave 1 cast (S/M/L/XL → 4/6/8/8); research-first findings **or** honest gaps |
| **Option 2 theatre (`2ba36c6`)** | Acts I–V on mission URL; Overview foyer; Specialists cast-first; Programme Lab; light project auto-attach |
| **Older build DAG (workforce)** | “Build a product” intent: charter → parallel research → PRD → gates → HTML prototype → static verify → release pack — largely **stubs** unless model mode + keys |
| **Policy** | Human gates, ceilings, disclosure, no fabricated evidence — encoded in `AGENTS.md` / PRD |

### Where it is thin

| Gap | Reality |
| --- | --- |
| **Feel of product-building** | Theatre stages an **investigation / decision pack** well. It does **not** yet feel like specialists **shipping a product through sequential build artefacts**. |
| **Agent depth** | Cast is a sized subset of catalogue roles + event chips. Contribution lines and ETAs are light. Specialists are not yet visibly owning successive deliverables. |
| **Stub vs keys** | Default path still leans **deterministic / simulated** when providers are off. Correct honesty; weak “agents are building” conviction. |
| **Two build stories** | Supervised PSI loop (primary) and workforce build lifecycle (older / secondary) are not one sequential product narrative on the stage. |
| **Project memory** | Auto-attach exists; the Project page is still a thin shelf — not the accumulating product the agents are building. |
| **Living work** | Event-driven and honest (no fake timers) — still closer to a **status scene** than a **workshop producing the next artefact**. |
| **G4 / G5** | Project memory and Programme Lab are light; experience track called deeper Project shelf and Programme acts language “remaining.” |

**Candid verdict:** The **spine and briefing theatre are shippable foundations**. The north star — *product-building agents* — is only half true today: agents **brief and investigate**; they do not yet **build products in sequence** as the thing you came to watch.

## 4. What to keep from B–E / Option 2 theatre

**Keep (do not reopen without cause):**

- Supervised mission as **primary URL** (no `/cases` fork).
- **Option 2 IA:** foyer → theatre → cast → Project shelf; Programme = Lab.
- **One-liner intake** and initiating **PM brief** before heavy work.
- **Human plan approval** before post-approve research/work pass.
- **Banded staffing** + catalogue intent as honesty labels (not “150 every time”).
- **Persisted-event living work** (no fake busy timers; no invented web).
- **Honesty badges**, not essay walls; ops chrome demoted.
- Binding Stage 1 rules: gates, ceilings, disclosure, no fabricated evidence, additive schema.

**Evolve (do not throw away):**

- Act V “living work” → **sequential build beats with inspectable artefacts**, not only research findings/gaps.
- Cast panel → **who owns the current beat and what they just handed off**.
- Project shelf → **timeline of artefacts + decisions** the product accumulated.
- Workforce build DAG contracts / gates → **feed the same theatre language**, not a second product.

**Do not revive as primary:** agents office, always-on 150 catalogue, programme KPI dashboard, Overview conversation dumps, fake cinematic timers, voice before typed path proves the build sequence.
