# DeliverX MVP — seven-step Studio journey

**Branch origin:** ChatGPT / Cursor work on `feat/idea-submission-step-one`, merged onto Phase A (`178acea`).  
**Intent:** Align the signed-in product with the founder brief’s *feel* without claiming design/engineering delivery is complete.

## What users get

| Step | Screen | Backed by |
|------|--------|-----------|
| 1 | Your idea — brief, optional context, scope review | `InvestigationScopeReview`, intake draft |
| 2 | AI analysis — event-backed themes / progress | `InvestigationExperience`, activity + research |
| 3 | PM briefing — plain-language recommendation | `InvestigationPmBriefingStage` |
| 4 | Discuss & decide — options, paths, explicit save | decision UI on supervised mission |
| 5 | Meet the team — roles from continuation plan / specialist tasks | `InvestigationTeamFormation` (record-backed status only) |
| 6–7 | Work in progress / iterate & deliver | theatre, project room, downloads |

Honest disclosures remain: status only from saved events; larger catalogue not shown as “active”; implementation still gated.

## Still not the full brief

- Named PM persona (“Aria”) as primary chat shell — conversation panels exist; not a full PM-chat product surface.
- Design → engineering → QA → full ZIP package of PRD/code/tests — **not** verified as an executed delivery loop.
- Live signed-in provider research proof — see `docs/psi-phase-a-preview-acceptance.md`.
- Landing marketing demo of the full loop — separate from Studio.

## MVP positioning (honest)

> Idea → investigation → PM briefing → your decision → assigned team plan → recorded progress → export of the investigation/decision record.

That is the trustworthy loop. Expanding to “build the app” requires the next milestone after this UI spine is on `main`.
