**Status:** Planning only — **not** an instruction to build. Awaits founder “go build phases…”

---

## 1. One-liner

**DeliverX is a supervised company of research-led AI agents that turns a one- or two-sentence idea into an honest, evidence-based product journey — go, no-go, or gap-led build — so founders, PMs, CEOs and learners get real sense-making, not a dashboard of roles.**

---

## 2. The problem

People with an idea (founders, PMs, students, small CEOs) face the same gap:

| Pain | Reality today |
| --- | --- |
| Ideas without diligence | Chat tools brainstorm; they rarely do deep, cited due diligence or say “don’t build this.” |
| Tools without a company | Agent directories and copilots show capabilities; they don’t staff a **product lifecycle** with ownership, handoffs and human gates. |
| Learning without doing | Courses explain “how to build a product”; they don’t put you inside a live case with specialists who research, argue trade-offs and ship artefacts. |
| Dashboards without meaning | Status, catalogues and empty “desks” don’t answer: who, why, what data, what evidence, what decision, what happened after. |

**Cost of the gap:** wasted build time on weak ideas; weak conviction on good ones; no durable trail of *why* a product existed.

## 4. The solution (product definition)

### 4.1 Core loop

```text
One-/two-line idea
  → Deep due diligence (market, competitors, failures, gaps)
  → Honest verdict (go / no-go / gap-led path)
  → If go: SWOT + white space + PM-forward plan
  → Staffing: who, why, what data
  → Agent collaboration with visible trail (who told whom what)
  → Human gates (plan, decisions, external acts)
  → Artefacts → thin build / prototype where appropriate
  → Expected vs observed outcome
  → Proposed next mission (never auto-started)
```

### 4.2 What agents must do (non-negotiable)

1. **Research-first due diligence** from configured sources (and honest gaps when sources are missing).  
2. **Hard truths:** saturated markets, prior failures, “don’t build” as a first-class outcome.  
3. **Evidence discipline:** facts vs assumptions vs unknowns; no fabricated customers or interviews.  
4. **Ask the human only when blocked** (missing proprietary data, need real interviews, decisions).  
5. **Company behaviour:** negotiate trade-offs (market, money, delivery); hand off with contracts.  
6. **Visible collaboration trail:** connections between agents — not a black box.  
7. **Personalized to the case:** staffing and depth scale with complexity; not “150 roles always on.”  
8. **Human supervision:** agents draft; humans approve; nothing external without explicit yes.

### 4.3 What the user must always see

For their case, at any serious step:

- **Who** is involved and **why**  
- **What data** is in play (and what’s missing)  
- **What entry / research moves** were chosen and why  
- **What was produced**  
- **What is blocked or waiting on them**  
- **What communication** passed between agents  
- **What we expected vs what we observed** after delivery  

AI contribution must stay distinguishable from the user’s own input.

## 10. Risks & mitigations

| Risk | Mitigation |
| --- | --- |
| Feels like another agent dashboard | Experience contract: forbid catalogue/ops as primary story; stage = diligence company. |
| Hallucinated research | Provider-backed retrieval only; disclose Simulated vs Model; gaps when no key. |
| Fake interviews | Rehearsal labelled; only founder-supplied notes count as evidence. |
| Scope explosion (150 always-on) | Complexity-banded staffing; Available vs Planned honesty. |
| “Don’t build” demotivates paid users | Position honesty as the product; save wasted build cost. |
| Dual spines (workforce vs supervised) confuse | One primary journey language; secondary tools under fold. |

## 12. Recommended strategic approach (for later phase planning)

When founder says go build phases, implement against an **experience contract**, not more shell chrome:

1. **Diligence company act** — research → verdict (go / no-go / gap).  
2. **Case room** — who, why, data, asks, artefacts on one stage.  
3. **Collaboration trail** — persisted handoffs between specialists.  
4. **PM-forward plan + staffed build** — only after go.  
5. **Outcome & next** — expected / observed / proposed follow-up.  
6. **Learner lens** — same artefacts, explicit “what you practiced” summary.

Defer: agents office as primary, catalogue as default, voice-only paths, always-on 150.
